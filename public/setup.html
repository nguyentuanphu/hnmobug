Start by getting the game running on your own machine. Then choose how to bring in friends, café guests, or a public community.

Set up on your own computer

Download and extract HNMO.zip, then use the launcher for your operating system.

Download HNMO free
Windows x86-64

PostgreSQL comes in the package. Double-click Start HNMO.bat and look for the HNMO tray icon. To see startup output in a window, use Start HNMO (window).bat.

macOS Apple Silicon · Intel

Download for macOS (Start HNMO.app)

Install PostgreSQL 16. Open Terminal in the HNMO folder and start HNMO. This example uses Homebrew.

brew install postgresql@16
./start-hnmo.sh
Linux x86-64

Download for Ubuntu/Debian (.deb)

Example for Ubuntu 24.04. Install PostgreSQL 16, then run the launcher from the HNMO folder as a regular user.

sudo apt update
sudo apt install postgresql-16
./start-hnmo.sh

First launch

  1. Allow a few minutes for initial database setup. On the host, open http://localhost:8080/control. If you see the first-start setup wizard, enter your game name, pick a language, keep the default ports, then select Save and start HNMO.
  2. On the host, open http://localhost:8095/users and create the first admin account with a password of at least 12 characters.
  3. To enable web registration, create an Administrator API key at localhost:8095/api-keys and enter it in the setup box at localhost:8080/account.html on the host. Keep the key private.
  4. Open http://localhost:8080, create a player account, and enter the game to check that it works. Use /control to check status, view logs, or take a backup.

Play on the same network

On the Windows host, run ipconfig and look for the Wi-Fi or Ethernet IPv4 address. On macOS or Linux, check Network Settings. If the host is 192.168.1.20, players on the same network open http://192.168.1.20:8080 in their browsers. Allow web port 8080 through the host firewall on the private network.

If a second device cannot connect, check that both devices are on the same network and that guest Wi-Fi is not isolating them.

Invite friends through Tailscale

Use this for an invite-only group when friends are on different networks. HNMO still runs on your computer.

  1. Download Tailscale. Install it and sign in on the HNMO host and on each friend’s device.
  2. In the Tailscale admin console, open Machines, select the HNMO host, and use Share to invite friends. They open and accept the invitation with their own Tailscale accounts.
  3. Copy the host’s Tailscale IPv4 address from its app or run tailscale ip -4. For example, if the host is 100.101.102.103, share http://100.101.102.103:8080.
  4. Have a friend open the link in a browser while Tailscale is connected. If it fails, confirm they accepted the invitation, HNMO is running, and the host firewall allows port 8080 from the Tailscale network.

Go public from home

You’ll need a host computer running HNMO, access to configure your router, a domain, and a public IP that can accept incoming connections.

  1. Check the router’s WAN address. If your connection is behind carrier-grade NAT or inbound access is blocked, ask your provider about a public IP or use a VPS. Tailscale works for an invite-only group.
  2. Reserve a LAN address for the host in your router, for example 192.168.1.20. Point the play.example.com A record to your router’s public IPv4. If the public address changes, update DNS.
  3. On the router, forward TCP ports 80 and 443 to the machine running the reverse proxy. Allow these ports in the host firewall. Keep the web port 8080, admin port 8095, and database ports private.
  4. Set up HTTPS using the example below. Use a phone on mobile data to open your domain, create a player account, and enter the game before sharing the link.

Run HNMO on a VPS

This example uses an Ubuntu 24.04 x86-64 VPS with a public IPv4 address and a regular SSH user with sudo access.

  1. Sign in over SSH. Install PostgreSQL 16 and extract HNMO under that user’s home folder. Use sudo for system packages and run HNMO as the regular user.
sudo apt update
sudo apt install postgresql-16 unzip curl
mkdir -p ~/games
cd ~/games
curl -fL https://hnmobug.netlify.app/download -o HNMO.zip
unzip HNMO.zip
cd HNMO
./start-hnmo.sh
  1. From your own computer, open an SSH tunnel using the command below. Replace user and vps.example.com with your account and VPS hostname. Keep this SSH terminal open while you set up HNMO.
ssh -N -L 8080:127.0.0.1:8080 -L 8095:127.0.0.1:8095 user@vps.example.com
  1. On your own computer, open localhost:8080/control and localhost:8095 through the tunnel. Create your admin, configure web registration, and enter the game using the first-launch steps.
  2. Point your domain’s A record at the VPS IPv4. Allow TCP 80 and 443 in both the provider firewall and the VPS firewall. Keep SSH for administration and send player traffic through HTTPS.
  3. Add the HTTPS configuration. Once it is running, use Install as a service in /control if the VPS supports it, then test a VPS restart to verify HNMO starts again.

HTTPS example for a public server

In HNMO’s Host settings, enter your domain in Public address. In Plugins, clear the website admin path to keep admin access on the host or through the SSH tunnel.

Download Caddy. On Ubuntu, you can install it with sudo apt install caddy. Run Caddy on the HNMO host and replace play.example.com with your domain.

play.example.com {
    @hostOnly path /control /control.html /control/* /api/control /api/control/*
    respond @hostOnly 404
    reverse_proxy 127.0.0.1:8080
}

Caddy forwards the game’s WebSocket connection and obtains a certificate when DNS and public ports are ready. If Caddy runs as a service on Ubuntu, add the block to /etc/caddy/Caddyfile, validate it, then reload the service.

sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy

If running Caddy directly at home, save the example into Caddyfile and run caddy run --config Caddyfile. From a separate network, verify that the game plays over HTTPS and the public /control path returns 404.
